# Литология по каротажу: что модель знает и чего не знает

[![tests](https://github.com/Alex91132/well-log-lithology/actions/workflows/tests.yml/badge.svg)](https://github.com/Alex91132/well-log-lithology/actions/workflows/tests.yml)

**[Страница с результатами и просмотром скважин](https://alex91132.github.io/well-log-lithology/)** ·
**[План](PLAN.md)** ·
[Сайт-портфолио](https://alex91132.github.io/)

LightGBM определяет породу в каждой точке ствола по каротажу (GR, RHOB, NPHI, DTC, сопротивления…) —
12 классов от песчаника до фундамента. Данные — реальное соревнование
[FORCE 2020](https://github.com/bolgebrygg/Force-2020-Machine-Learning-competition) (Норвежский шельф):
98 обучающих скважин, 10 открытых тестовых, 10 скрытых, на которых организаторы оценивали финалистов.
Модель упакована в сервис на FastAPI с Docker и проверками входных данных.

Главное в проекте — не модель, а проверка: [PLAN.md](PLAN.md) закоммичен (`4abc315`) до первой оценки
на скрытых скважинах, и скрытый тест запускался один раз, после выбора модели.

## Результат

| | Score (0 — идеал) | Точность |
|---|---:|---:|
| CV по случайным точкам — как делать не надо | −0,172 | 93,5 % |
| CV по скважинам (GroupKFold, 5 фолдов) | −0,653 | 74,8 % |
| Открытый тест, 10 скважин | −0,508 | 79,9 % |
| **Скрытый тест, 10 скважин — финальная оценка** | **−0,585** | **78,0 %** |

Score — метрика соревнования: −(средний штраф по матрице ошибок), где «глина вместо алевритистой глины»
стоит дешевле, чем «соль вместо песчаника».

* **Место среди финалистов — 13 из 14.** Победитель набрал −0,469, двенадцатое место −0,526.
  Модель не выиграла бы соревнование — и проект не про это.
* **Случайное разбиение обманывает в 3,4 раза.** Соседние точки одной скважины (шаг 15 см) почти одинаковые:
  CV по точкам экзаменует модель на «соседях» обучающих точек и обещает −0,17 вместо реальных −0,59.
* **CV по скважинам честен, но скважины очень разные.** Score случайного набора из 10 скважин в CV гуляет
  от −0,90 до −0,47 (5–95 %), открытый и скрытый тесты — внутри этого коридора.
* **Треть штрафа — одна скважина.** 17/4-1 вскрывает цехштейновые соли: score −1,30, на остальных девяти −0,468
  (уровень победителя). Разбор — ниже.

## Что дала каждая ступень

| Модель | CV по скважинам | Открытый тест |
|---|---:|---:|
| Константа «везде глина» | −1,153 | −1,164 |
| Логистическая регрессия | −0,869 | −0,816 |
| LightGBM: сырые кривые | −0,763 | −0,612 |
| LightGBM: + стратиграфия (группа, свита) | −0,702 | −0,579 |
| **LightGBM: + признаки по глубине** | **−0,653** | **−0,508** |

Признаки по глубине — окна 0,75 и 3 м, градиенты, GR в масштабе своей скважины, каверны (CALI − BS),
расхождение нейтрон — плотность. Все считаются внутри одной скважины — это проверено тестом.

**Выбор с учётом штрафов не пригодился.** Вместо самого вероятного класса можно брать класс с минимальным
ожидаемым штрафом (вероятности × матрица). На CV это +0,002 — меньше порога 0,005 из плана, поэтому в финале
обычный argmax. На скрытых скважинах штрафной выбор был бы хуже: −0,624.

## Можно ли верить вероятностям

* Модель самоуверенна на новых скважинах: заявляет 65 % — права в 52 % (ECE 0,13 на CV).
  Калибровка температурой (сверх плана, T ≈ 2) исправляет это на CV, на открытом тесте — частично (0,087 → 0,075).
* Как порядок уверенность полезна: если отдать геологу 20 % самых неуверенных точек, точность остальных — 82 % вместо 75 %.
* Модель ошибается там же, где сомневался интерпретатор: где геолог был уверен, она права в 78 % случаев,
  где сомневался — в 54–60 %.

## Разбор провала: скважина 17/4-1 (после финальной оценки)

42 % её интервала — соли цехштейна; галит в обучении есть лишь в трёх скважинах из 98. 3 325 точек галита модель
назвала глиной: гамма-каротаж там ≈ 6 API — у глины так не бывает, но плотность и нейтронный каротаж записаны лишь
на 11 % этих точек, а свита Smith Bank в обучающих скважинах почти всегда глинистая. CV это предвещал: галит распознан
лишь в 17 % случаев.

Гипотеза — модель переобучилась на категориальный признак «свита». Скрытые скважины уже вскрыты, поэтому она
проверяется только на CV и открытом тесте, без подгонки под финал (`scripts/run_posthoc.py`):

| Вариант | CV по скважинам | Открытый тест | Галит распознан (CV) |
|---|---:|---:|---:|
| Как в финале | −0,653 | −0,508 | 17 % |
| Без признака «свита» | −0,669 | −0,509 | 12 % |
| Регуляризация категорий | −0,653 | −0,493 | 17 % |

**Гипотеза не подтвердилась.** Без свиты модель хуже и в целом, и на галите; регуляризация меняет CV в пределах шума —
по правилу плана модель не меняется. Причина не в переобучении, а в данных: значимых примеров галита — две скважины.
Никакая настройка этого не исправит, поэтому правильный ответ — не прятать проблему, а помечать такие скважины.
Сервис помечает 17/4-1 сам: средняя уверенность 0,51 при пороге 0,61 (5-й перцентиль по скважинам CV). Проверка
добавлена после разбора, поэтому это иллюстрация, а не независимая оценка.

## Сервис

```bash
docker build -t litho .
docker run -p 8000:8000 litho                                       # http://localhost:8000/docs
curl -F "file=@examples/well_25_11-24.las" "localhost:8000/predict"
```

`POST /predict` — LAS 2.0 или CSV; `POST /predict/json` — кривые в JSON; `GET /model` — версия и метрики.
В ответе — литология и уверенность по глубине, доли пород и предупреждения:

* **нет ключевых кривых или они записаны не на всём интервале** (у 17/4-1: PEF нет, NPHI — на 40 %);
* **медиана кривой вне диапазона обучающих скважин** — ошибка единиц: плотность в кг/м³, нейтронный каротаж
  в процентах, DTC в мкс/м вместо мкс/фут (проверено на реальной скважине);
* **средняя уверенность ниже, чем у 95 % скважин валидации** — скважина не похожа на обучающие.

Сначала дрейф проверялся PSI со стандартными порогами 0,1 / 0,25 — тревога горела на *каждой* скважине: одна скважина
всегда отличается от смеси 98 (свой диаметр долота, свой интервал). Порог по 99-му перцентилю PSI обучающих скважин
всё равно сработал на нормальной короткой скважине. PSI остался в ответе для мониторинга, но тревогу не поднимает.

На 20 тестовых скважинах предупреждения получили пять. Самая плохая (17/4-1) помечена по уверенности, но вторая
и третья худшие прошли без предупреждений, а неполная кривая ещё не значит плохой прогноз — детектор не всеведущ.

Модель — артефакт `models/` (бустинг + `meta.json`: версия, признаки, категории, температура, пороги).
Docker-образ в CI собирается и проверяется запросом на реальной скважине.

## Запуск исследования

```bash
python -m venv .venv
.venv/Scripts/activate              # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python scripts/run_experiments.py   # скачает данные (157 МБ, сверит SHA-256), CV и открытый тест — ~40 мин
python scripts/train_final.py       # модель → models/
python scripts/evaluate_hidden.py   # один раз: скрытые скважины
python scripts/run_posthoc.py       # разбор после финала
python scripts/export_demo.py       # данные для docs/
pytest -q
```

## Структура

```
PLAN.md                 план, зафиксированный до финальной оценки
src/litho/
  data.py               загрузка с проверкой SHA-256, классы, штрафная матрица, метрика
  features.py           признаки внутри скважины
  models.py             ступени модели, решение с учётом штрафов
  validation.py         CV по точкам и по скважинам, калибровка, покрытие
  artifact.py           артефакт модели, проверки входных данных, калибровка температурой
  service.py            FastAPI
scripts/                эксперименты, финальная модель, оценка на скрытых, разбор, экспорт
results/                все таблицы и метрики (CSV, JSON)
examples/               скважина 25/11-24 из открытого теста в LAS и CSV
docs/                   страница GitHub Pages
tests/                  метрика против эталона соревнования, отсутствие утечек между скважинами, сервис
```
